# 多轮问数与流式运行

当前实现自然语言问题到 SQL 和结果表格的完整路径。数据源为内置电商业务库 `business`，使用服务端 Qwen 配置，前端不会接收连接凭据或 API Key。

## 使用方式

1. 按 README 初始化数据库并生成业务数据。已有第一阶段数据库在 `backend/` 执行 `python -m alembic upgrade head`。
2. 在 `backend/.env` 配置 `APP_DATABASE_URL`、`BUSINESS_READONLY_DATABASE_URL` 和 `QWEN_API_KEY`，确认模型名与 API 地址可用。
3. 启动前后端，在“问数分析”页选择推荐问题或输入自己的问题。
4. 查看结果表格、实际执行的 SQL、时间范围、假设和执行记录；历史会话在应用库中保存。

同一会话支持多轮追问和澄清续接。关键口径或字段歧义返回 `clarification_required`，可以直接提交简短答复。工作台使用 SSE 展示实时进度，支持停止分析；原有 JSON 接口保留。查询成功后还会生成受约束图表及基于结果的总结，支持图表类型切换和历史恢复。

## 多轮上下文与条件覆盖

每轮创建时从应用库加载本会话最近成功方案，以及其后的最近待澄清方案，保存为 `input_context`。只传递问题、参考时间和查询方案，不传递结果行，也不递归复制完整历史。失败、取消及运行中的记录不作为继承来源；成功的澄清答复结束此前的待澄清问题。无需启用 checkpoint，刷新页面或重启后仍可继续。

模型在 `QueryDraft.context_mode` 中区分独立问题 `new`、追问 `follow_up` 和澄清答复 `clarification`，并返回完整的 `resolved_question`、指标、时间、`filters`、`group_by` 与口径假设。前端展示这些条件及来源，查看较早结果不改变追问来源。

- “按品类拆分”继承指标、筛选和时间，替换原分组；“同时按天和品类”才保留多个分组。改变分组不自动删除筛选。
- “改成最近 7 天”覆盖时间，其余条件保持；相对时间按本轮参考时间计算。未修改时间的追问继承原绝对边界。
- “只看华南”覆盖对应区域筛选；“所有区域”移除该筛选。
- 澄清答复接续待澄清方案的完整条件，多次澄清将已确定条件保存在新方案中。
- 明确的独立新问题重置条件；点击“新建分析”建立空上下文。没有指代来源或关键条件时先澄清。

语义继承和条件覆盖由模型解析，服务端校验历史来源、指标及 SQL 的结构与权限。旧运行 JSON 的新增字段有默认值，无需新增数据库迁移；旧 SQL 仍作为理解历史的参考，并按当前 Schema 重新校验。

## 查询流程

LangGraph 加载实时允许的 Schema、应用内说明及指标 YAML，调用 Qwen 输出 `QueryDraft`，校验 SQL 后执行查询。模型输出格式错误、字段解析错误、可修复的数据库语法或类型错误最多修复两次，即总共三次生成。写操作、越权表、危险函数立即终止；模型服务故障、数据库连接错误、超时不自动重复执行。

参考时间在提交时以 `Asia/Shanghai` 捕获并保存，纠错沿用同一时间。新问题未指定时间时使用参考时间前最近 30 天，并明确显示假设；显式时间范围优先。新运行提示词版本为 `query-v3`，Schema 版本、上下文快照和指标 ID 随运行记录保存，旧记录保留原版本。时间范围和统计口径由模型生成，实际正确性需结合 SQL 和查询结果核对。

每次模型调用超时为 60 秒，模型认证、额度限制和超时返回不同错误码。结果总结独立调用最多 30 秒，不重试；前端单轮请求等待最多 300 秒，覆盖生成、有限纠错、查询及总结预算。模型使用异步调用，停止时关闭客户端；同步数据库工作在独立线程中执行，取消时向当前 PostgreSQL 连接发送取消请求，并等待事务、游标和连接清理完成。

SQLGlot 区分真实表、CTE 与派生子查询，限定单条 SELECT、允许的表、字段、Schema、函数及类型转换。执行前再次校验并规范化表名。业务连接采用只读事务，`search_path` 固定为 `pg_catalog`，防止同名自定义函数覆盖允许的内置函数。服务器游标和外层 LIMIT 限制返回最多 1,000 行；行 JSON 累计超过 2 MB 时也标记截断。查询超时为 10 秒，锁等待为 2 秒。

金额 `NUMERIC` 使用十进制字符串返回，日期时间使用 ISO 8601；列按位置对应行数组，因此重复列名不会覆盖数据。空结果是成功状态。前端排序及每页 50 行的分页只操作已返回数据，不重新执行 SQL。

## 图表与总结

执行成功后运行保持 `running`，继续 `build_chart` 和 `summarize_result` 节点，最后保存终态。表格先通过 `result` 事件展示，再发布图表和总结。图表根据真实列类型构建，使用列位置，避免重复 SQL 别名覆盖；单个时间/分类维度或时间加分类系列可自动绘图，最多四个指标、十二个系列、100 项非时间分类。时间默认折线、分类默认柱状；明确占比、单指标、不超过八项且完整非负时允许饼图，零合计或空值不生成饼图。结果截断时注明覆盖范围。不适合绘图的数据返回 `chart_message`，表格仍可查看。

`AnalysisRun.chart` 保存图表类型、标题、横轴列位置、数值列位置、可选系列列位置和允许切换的类型。前端据此构造 ECharts 配置，切换复用原结果；悬浮提示显示原始数值，精确金额以表格为准。

`AnalysisRun.summary` 保存纯文本及服务端附加的数据限制，`summary_prompt_version=summary-v1`。总结仅提供完整查询条件、使用的指标口径、最多 20 行/40 列/12 KB 样本和返回行数值统计，长文本每格最多 200 字符；不会发送全表结构、连接凭据或完整历史。数值摘要用十进制计算，`returned_values_sum` 只表示返回单元格的算术和。提示词要求遵守口径，不外推未提供数据或因果关系；模型总结仍需结合原始表格核对。空结果无需模型调用；截断、样本省略和采样限制均明确展示。

总结超时、模型故障或无效输出时，运行仍为 `succeeded`，保留表格及图表，保存 `summary_error` 和失败步骤。查询完成后在总结阶段停止，关闭模型客户端，保存已完成的成功结果及停止提示；查询完成前取消仍保存 `cancelled`。新增字段使用默认值，旧记录无需迁移。

## 接口

全部接口以 `/api/v1` 开头。

| 方法与路径 | 输入及响应 |
|---|---|
| `POST /conversations` | `{}` 或 `{"datasource_id":"business","title":"分析标题"}`，返回 201 与会话摘要 |
| `GET /conversations?offset=0` | 按创建时间倒序返回最多 50 个会话 |
| `GET /conversations/{id}` | 会话摘要及最近 50 个运行记录，运行按时间正序 |
| `POST /conversations/{id}/messages` | `{"question":"最近30天的实付销售额和支付订单数"}`，返回完整运行记录 |
| `GET /runs/{id}` | 读取完整持久化运行记录 |
| `POST /conversations/{id}/messages/stream` | 与 JSON 提交相同的输入，以 `text/event-stream` 返回进度与结果 |
| `POST /runs/{id}/cancel` | 停止当前服务中的流式运行，等待清理和持久化，返回完整运行记录；已终止记录直接返回 |

`AnalysisRun` 包含状态、问题、参考时间、生成方案、结构版本、结果、步骤耗时、累计 Token 用量以及错误码。运行状态为 `running`、`succeeded`、`failed`、`clarification_required` 或 `cancelled`。业务失败在 200 响应的运行记录中表达；参数错误为 422、记录不存在为 404、未配置模型或应用库故障为 503。错误信息不包含连接串、Key 或原始驱动、供应商异常。

## 流式事件与运行生命周期

SSE 每条事件包含 `type` 和 `run_id`，事件名与 `type` 一致：

| 事件 | 内容 |
|---|---|
| `run_started` | 已创建的运行记录，包括参考时间和模型版本 |
| `node_status` | 当前步骤的开始或结束状态、尝试次数、耗时、诊断、结构版本和累计 Token 用量 |
| `sql` | 当前查询方案；校验通过后再次发送规范化 SQL，执行前仍可能被拒绝 |
| `result` | 查询结果；图表、总结及完整运行状态尚待完成 |
| `chart` | 受约束图表配置及绘图限制提示 |
| `summary` | 完整结果总结或降级提示、总结提示词版本 |
| `run_completed` | **已持久化**的完整终态记录，可为成功、失败、需澄清或已取消 |
| `stream_error` | 终态未能保存，客户端提示刷新历史确认状态 |

步骤状态为 `running`、`succeeded`、`failed` 或 `cancelled`。同一节点、同一次尝试的结束事件更新已有步骤。空闲时每 10 秒发送注释心跳；响应关闭代理缓冲及缓存。事件 ID 标识本次流内顺序，当前不支持事件重放；断线后通过历史记录恢复最终状态。

运行记录创建失败、未配置模型或记录不存在时，在流开始前返回普通 HTTP 错误。流开始后的业务失败通过 `run_completed` 中的错误码表达。一个会话同一时间只允许一个分析，JSON 和流式提交共用会话占用标记，重复提交返回 409。

点击停止、流连接断开、离开问数页及应用正常退出时，取消尚未完成的分析，停止后续节点并等待连接清理，随后保存 `cancelled` 和完成时间；如果查询已经完成，则保留成功结果并记录总结停止提示。前端停止按钮等待服务端确认后解除输入锁定；取消请求失败时保留可重试的停止操作。查询已结束、正在保存终态时，停止操作等待已有结果保存，完成结果优先。

运行管理采用进程内注册表，适用于本地单进程启动；请勿为此工作台配置多个 Uvicorn worker。原有 JSON 提交接口保持整轮响应语义，不接入流式取消注册表，断线可能继续执行。进程被强制终止或数据库无法保存终态时，记录仍可能停留在 `running`；取消接口对不在当前服务中的 `running` 记录返回 409，提示重新提交。当前未启用 LangGraph checkpoint 恢复。

## 验证

普通 pytest 验证 SQL 边界、有限纠错、模型故障、接口契约、错误脱敏、SSE 事件顺序、断线取消、重复停止、启动及退出竞态、保存失败、历史来源约束及旧记录兼容。前端测试覆盖 UTF-8 与 CRLF 分片解析、实时状态更新、停止、断线恢复、澄清继续和完整口径展示。配置 `WHITEBEAR_TEST_ADMIN_URL` 后，集成测试创建独立临时数据库和角色，验证迁移、真实只读查询、行数截断、金额精度、SQL 失败后的连接清理、固定时间销售与订单结果、真实 PostgreSQL 取消后的连接释放、取消状态、跨应用实例的历史恢复，以及 JSON/SSE 多轮条件覆盖、澄清续接和失败记录隔离，完成后清理临时资源。

CI 使用模型桩，无需真实 Key。真实 Qwen 可在工作台手动验收推荐问题；50 个固定问题和 90% 正确率仍属于后续评测目标，不代表当前已完成评测。
