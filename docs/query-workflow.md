# 第二阶段：单轮问数

当前实现自然语言问题到 SQL 和结果表格的完整路径。数据源为内置电商业务库 `business`，使用服务端 Qwen 配置，前端不会接收连接凭据或 API Key。

## 使用方式

1. 按 README 初始化数据库并生成业务数据。已有第一阶段数据库在 `backend/` 执行 `python -m alembic upgrade head`。
2. 在 `backend/.env` 配置 `APP_DATABASE_URL`、`BUSINESS_READONLY_DATABASE_URL` 和 `QWEN_API_KEY`，确认模型名与 API 地址可用。
3. 启动前后端，在“问数分析”页选择推荐问题或输入自己的问题。
4. 查看结果表格、实际执行的 SQL、时间范围、假设和执行记录；历史会话在应用库中保存。

每个问题独立分析。会话当前仅组织历史，追问必须写出完整条件。关键口径歧义返回 `clarification_required`，补充条件后重新提交。请求完成后一次返回 JSON；SSE、断线取消、多轮条件继承、图表及总结属于第三阶段。

## 查询流程

LangGraph 加载实时允许的 Schema、应用内说明及指标 YAML，调用 Qwen 输出 `QueryDraft`，校验 SQL 后执行查询。模型输出格式错误、字段解析错误、可修复的数据库语法或类型错误最多修复两次，即总共三次生成。写操作、越权表、危险函数立即终止；模型服务故障、数据库连接错误、超时不自动重复执行。

参考时间在提交时以 `Asia/Shanghai` 捕获并保存，纠错沿用同一时间。提示词要求未指定时间时使用参考时间前最近 30 天，并明确显示假设；显式时间范围优先。提示词版本为 `query-v1`，Schema 版本和指标 ID 随运行记录保存。时间范围和统计口径由模型生成，实际正确性需结合 SQL 和查询结果核对。

每次模型调用超时为 60 秒，模型认证、额度限制和超时返回不同错误码。前端单轮请求等待最多 240 秒，覆盖首次生成及两次纠错的调用预算。

SQLGlot 区分真实表、CTE 与派生子查询，限定单条 SELECT、允许的表、字段、Schema、函数及类型转换。执行前再次校验并规范化表名。业务连接采用只读事务，`search_path` 固定为 `pg_catalog`，防止同名自定义函数覆盖允许的内置函数。服务器游标和外层 LIMIT 限制返回最多 1,000 行；行 JSON 累计超过 2 MB 时也标记截断。查询超时为 10 秒，锁等待为 2 秒。

金额 `NUMERIC` 使用十进制字符串返回，日期时间使用 ISO 8601；列按位置对应行数组，因此重复列名不会覆盖数据。空结果是成功状态。前端排序及每页 50 行的分页只操作已返回数据，不重新执行 SQL。

## 接口

全部接口以 `/api/v1` 开头。

| 方法与路径 | 输入及响应 |
|---|---|
| `POST /conversations` | `{}` 或 `{"datasource_id":"business","title":"分析标题"}`，返回 201 与会话摘要 |
| `GET /conversations?offset=0` | 按创建时间倒序返回最多 50 个会话 |
| `GET /conversations/{id}` | 会话摘要及最近 50 个运行记录，运行按时间正序 |
| `POST /conversations/{id}/messages` | `{"question":"最近30天的实付销售额和支付订单数"}`，返回完整运行记录 |
| `GET /runs/{id}` | 读取完整持久化运行记录 |

`AnalysisRun` 包含状态、问题、参考时间、生成方案、结构版本、结果、步骤耗时、累计 Token 用量以及错误码。运行状态为 `running`、`succeeded`、`failed` 或 `clarification_required`。业务失败在 200 响应的运行记录中表达；参数错误为 422、记录不存在为 404、未配置模型或应用库故障为 503。错误信息不包含连接串、Key 或原始驱动、供应商异常。

连接断开时第二阶段查询可能继续，最终记录可从历史读取。若后端进程被终止，已创建的记录可能停留在 `running`，可重新提交；运行恢复和取消随第三阶段实现。当前未启用 LangGraph checkpoint 恢复，初始化的 checkpoint 表留给后续会话流程。

## 验证

普通 pytest 验证 SQL 边界、有限纠错、模型故障、接口契约及错误脱敏。配置 `WHITEBEAR_TEST_ADMIN_URL` 后，集成测试创建独立临时数据库和角色，验证迁移、真实只读查询、行数截断、金额精度、SQL 失败后的连接清理、固定时间销售与订单结果及跨应用实例的历史恢复，完成后清理临时资源。

CI 使用模型桩，无需真实 Key。真实 Qwen 可在工作台手动验收推荐问题；50 个固定问题和 90% 正确率仍属于后续评测目标，不代表当前已完成评测。
